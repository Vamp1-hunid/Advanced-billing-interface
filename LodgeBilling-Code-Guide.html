The app in 30 seconds

Lodge Billing is a JavaFX desktop app for a lodge’s front desk. The receptionist types a guest’s details, the app works out the bill, and saved bills appear in a table. From the table you can view a till-style receipt, print it, or delete the bill. There is a light/dark theme and full keyboard support.

Your one-paragraph pitch (memorise this) “Lodge Billing follows MVC. The model holds the data and the billing rules. Its bills are in an ObservableList and its status and theme are properties. The view classes build the screen from JavaFX layout panes and controls, and they watch the model. The controller handles every user action through a BillingActions interface: it reads the form, validates it, updates the model and tells the view what to do next. Because the views observe the model, the table and status bar update themselves whenever the data changes.”

Listener or binding? Use a binding when one value should simply follow another (the button text follows the theme) U2 · 22. Use a listener when a change should run some code (swap CSS classes, clear an error) U2 · 21. “Normal list: changes silently. ObservableList: changes loudly” U2 · 23.

The golden thread rule U2 · 10

All scene-graph changes must happen on the JavaFX Application Thread, and long work must not block it. In Lodge Billing every action is instant (no database or network), so it all runs safely inside event handlers. The one explicit use of the thread is Platform.runLater in MainView.install, which queues “focus the name field” to run on the UI thread after the window appears. If you later add a database, Unit 2 says to move the slow call off the UI thread (for example with a JavaFX Task) and update the screen afterwards.

171    /** A row of paper-coloured teeth for the torn top or bottom edge. */
172    private static Polygon edge(boolean top) {
173        Polygon teeth = new Polygon();
174        double flat = top ? TOOTH : 0;     // the straight side touching the paper body
175        double tip = top ? 0 : TOOTH;      // the pointed side
176        for (double x = 0; x < PAPER_WIDTH; x += TOOTH * 2) {
177            teeth.getPoints().addAll(x, flat, x + TOOTH, tip);
178        }
179        teeth.getPoints().addAll(PAPER_WIDTH, flat);
180        teeth.getStyleClass().add("receipt-edge");
181        return teeth;
182    }
183}
What

Draws the torn zig-zag edge for the top or bottom of the paper.

How

A Polygon is a shape made from a list of points (x1, y1, x2, y2…). The loop adds a point every 10 px, alternating between the flat side and the tip, which makes triangles ("teeth"). For the top edge the tips point up; for the bottom they point down. The final point closes the shape at the right edge.

Pure decoration that makes the receipt feel real, built from the same scene-graph nodes as everything else U2 · 9.

Defence questions, with model answers

These include every exit question from your slides plus the questions examiners most often ask about this kind of project. Try to answer out loud before opening each one.

What did you build, and which node is the root? Unit 2 exit ticket U2 · 28

A JavaFX desktop billing system for a lodge: enter a guest’s stay, calculate and save the bill, see saved bills in a table, view/print a receipt, delete a bill. The root node of the Scene is MainView, which extends BorderPane: menus, toolbar and header on top, the work area in the center.

Identify the Stage, the Scene and at least three Nodes in your app. Unit 2 U2 · 8

Stage: the window titled “Lodge Billing” (passed into start(Stage)). Scene: new Scene(controller.view(), width, height). Nodes: the Guest name TextField, the Room type ComboBox, the Save Button, the bills TableView, the status Label, and layout panes such as GridPane and VBox.

What is MVC and how does your program use it? Lecture 1 L1 · 11 L1 · 37

MVC splits an app into Model (data and rules), View (what the user sees) and Controller (what happens when the user acts). The packages are named after the roles: model (BillingModel, Bill, BillValidator…), view (MainView, BillFormView, BillTableView…), controller (BillingActions, BillingController). Views report clicks to the controller through an interface; the controller validates and updates the model; views update themselves because they observe the model.

Why is MVC useful in a JavaFX application? Lecture 1 L1 · 9 L1 · 37

It avoids “spaghetti GUI code”. Each class has one reason to change: changing a price touches RoomType only; restyling touches only CSS; the rules can be tested without a window; and a different screen (or a database) can be added without rewriting the rules.

Trace what happens when the user clicks Save bill. Lecture 1 L1 · 13 L1 · 19

The button’s handler calls actions.saveBill(). The controller calls readForm(), which asks the view for a BillFormData and gives it to BillValidator.validate. If invalid, it shows the message, outlines and focuses the field, and stops. If valid, it checks that this guest has no bill yet (findByGuest), then calls model.save(input), which creates “B001” and does bills.add(bill). The ObservableList notifies the TableView, which adds a row. The controller sets a success status (the StatusBar turns green) clears the form and asks the view to scroll to the bill.

Why does adding to an ObservableList update the table? Lecture 3 exit question L3 · 30

Because the table was given that very list with setItems(bills), and doing so registers the table as a listener on the list. An ObservableList fires a change event on every add/remove (“a list with an alarm” L3 · 16), and the table reacts by adding or removing the row. A normal ArrayList changes silently, so the table would never know.

What is the difference between an ObservableList and an ArrayList? Unit 2 U2 · 23

Both store items, but an ObservableList also notifies listeners whenever it changes. “Normal list: changes silently. ObservableList: changes loudly.” It is created with FXCollections.observableArrayList().

What is a property? What is a binding? When do you use each? Unit 2 U2 · 21 U2 · 22

A property is a value JavaFX can watch (e.g. ObjectProperty<Theme>, a TextField’s textProperty()). A listener runs code when it changes (StatusBar swaps CSS classes). A binding keeps another property always equal to an expression (the theme button’s text is bound to “theme is LIGHT ? Dark mode : Light mode”). Binding = follow a value; listener = do something.

Which control would you use for a long comment, and why? Lecture 3 exit question L3 · 30

A TextArea, as used for Notes. It accepts several lines, setWrapText(true) wraps long text and setPrefRowCount(2) sets its height L3 · 8. We also made Tab leave the area so keyboard users are not trapped.

What happens when a user cancels a deletion? Lecture 3 exit question L3 · 30

confirmDelete returns false: either Cancel was pressed or the dialog was closed (orElse(ButtonType.CANCEL) treats closing as Cancel). The controller shows “Deletion cancelled.” and returns before model.delete, so the bill stays. Cancel is also the default button, so pressing Enter keeps the bill.

Why should validation preserve the entered text? Lecture 3 exit question L3 · 30 L3 · 27

So the user only has to fix the one wrong field instead of retyping everything. In Lodge Billing a failed check only sets a message and moves the focus; the form is not cleared. It is cleared only after a successful save (or New guest), exactly as Lecture 3 advises: “clear fields only after this save succeeds” L3 · 20.

Explain one job of the Controller and one job of the DAO. Lecture 3 exit question L3 · 30 L3 · 28

Controller: respond to UI actions, e.g. saveBill() reads and validates the form and asks the model to save. DAO: read and write stored data. In this project BillingModel plays that role in memory (save, delete, the list); with a database it would call a BillRepository using JDBC.

Where are the business rules? Why not in the controller? Lecture 1 L1 · 12 L1 · 35 · Unit 2 U2 · 20

In the model: Bill (room charge, 5% discount for 5+ nights, total, balance), BillValidator (input rules) and RoomType (prices). Keeping them out of the controller keeps it thin and keeps the rules testable without a GUI. Mini Lab 2 asks you to “prove the controller does not contain the rule”: BillingController contains no arithmetic.

Why use BigDecimal instead of double for money? Money.java

double is binary and cannot represent many decimals exactly (0.1 + 0.2 = 0.30000000000000004). BigDecimal is exact, and setScale(2, RoundingMode.HALF_UP) rounds like a cashier. Prices are even created from Strings (new BigDecimal("550.00")) to stay exact.

Why is Bill immutable? What does that mean? Lecture 3 L3 · 15 · Lecture 1 L1 · 20

All fields are private final, totals are computed once in the constructor, and there are only getters. So a bill cannot change after creation: its total can never disagree with its nights or extras, and the same object can safely be shown in the table, the receipt and the printout.

Why do you have BillFormData, BillInput and Bill? Isn’t that repetition? Lecture 1 L1 · 25

They are three different stages, exactly Lecture 1’s “form controls → command → entity”. BillFormData is the raw text (a DTO); BillInput is the checked command (int nights, BigDecimal money); Bill is the entity with an id and calculated totals. Separate types mean the compiler stops anyone building a Bill from unchecked text.

What is BillingActions and why does the view use it instead of BillingController? Lecture 1 L1 · 26

It is an interface listing every user action. The controller implements it; the views only know the interface. That is a dependency boundary: the view depends on a contract, not a concrete class, so the controller could be replaced (or faked in a test). It also means a toolbar button, a menu item and a shortcut all call the same method.

How does validation tell the user which field is wrong? Lecture 1 L1 · 27 · Lecture 3 L3 · 12

BillValidator throws a ValidationException carrying a friendly message and a FormField. The controller catches it, stores StatusMessage.error(message, field) in the model and focuses that field. The StatusBar shows the red message and BillFormView switches on the :error pseudo-class for that field (red outline). Editing that field clears the error.

Why is ValidationException a checked exception? Lecture 1 L1 · 27

Lecture 1: “use checked exceptions when the caller can reasonably recover”. An invalid form is expected and recoverable (show a message, let the user fix it). Being checked, the compiler forces the controller to handle it, so a validation error can never crash the app or show a stack trace.

What does PropertyValueFactory("guestName") do? Any risk? Lecture 3 L3 · 18

For each row it calls the Bill’s getter getGuestName(), found by name at run time (reflection). The risk is that renaming the getter is not a compile error: the column just goes blank. A lambda cell value factory (Unit 2’s style U2 · 24) is checked by the compiler.

How do you stop a guest getting two bills? BillingModel.findByGuest

Before saving, the controller calls model.findByGuest(name), which compares names after normalise (trim, single spaces, lower case). If a bill exists, the controller shows “A bill for Mary Banda is already saved as B001.” tied to the name field (red outline, cursor there) and does not save. Deleting that bill allows the guest to be billed again. The search lives in the model (a repository-style method); the controller only reacts to the answer.

Why did you choose GridPane, BorderPane, VBox and HBox where you did? Unit 2 U2 · 11

BorderPane for the main window’s regions (top bar, center work area) U2 · 12; GridPane for the form so labels and inputs line up U2 · 13; VBox/HBox for simple stacking such as button bars, cards and receipt lines U2 · 14; StackPane to centre the receipt U2 · 15. No fixed x/y positions, so everything resizes.

How does the app support keyboard users and accessibility? Lecture 3 L3 · 26

Save is the default button (Enter); every label is linked with setLabelFor and has an Alt mnemonic; the cursor starts in Guest name; Tab moves logically and leaves the Notes area; menu shortcuts (Ctrl+N/R/P/D/T/Q); a visible gold focus border; the status bar has accessible text; errors use words as well as colour.

How does dark mode work? Unit 2 U2 · 21 · Lecture 1 L1 · 21

The controller flips the model’s theme property. What is Platform.runLater and why do you use it? Unit 2 U2 · 10

It queues code to run on the JavaFX Application Thread a moment later. We use it to focus the Guest name field after the window has appeared, because focus cannot be given to a node that is not on screen yet. It also respects the golden thread rule: UI changes on the UI thread.

What does showAndWait() do? Lecture 3 L3 · 22 L3 · 23

It opens a dialog as modal: the code pauses until the user closes it, then returns the clicked button as an Optional<ButtonType>. That is why confirmDelete can return true/false directly.

Why didn’t you use FXML? Unit 2 U2 · 18 U2 · 27

The project follows Unit 2’s Round 1 (plain Java). Separation is still kept: view classes only build controls and forward clicks through BillingActions. Converting a view to FXML would be mechanical, and javafx.fxml is already in build.gradle.
